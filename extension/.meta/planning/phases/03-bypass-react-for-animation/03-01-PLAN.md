<objective>
Bypass React for animation frame updates by making animateTick call renderer.setDynamicState() imperatively via a callback, eliminating ~9 React re-renders per expand/collapse animation.

Purpose: This is the critical optimization — Phase 2 gave us the granular API, but React still re-renders on every animation tick because animateTick calls setAnimationVersion(v+1) each frame. Removing this re-render loop eliminates the entire cascade: renderNodes useMemo, connectionPositions useMemo, buildConnections, and the setDynamicState useEffect — all of which currently fire 9+ times per 150ms animation.

Output: animateTick pushes position/openProgress updates directly to the renderer without touching React state. React reconciles once at animation end.
</objective>

**Strategy — onTickRender callback pattern:**

A callback injected from GraphCanvas into useGraphAnimation. useGraphAnimation calls the callback each tick instead of setting React state. GraphCanvas builds the DynamicGraphState and pushes it to the renderer.

1b. In `animateTick`, replace `invalidateAnimation()`/`invalidateParticles()` calls during active ticks:
```typescript
const tickRender = onTickRenderRef.current;
if (nodesDirty || openDirty) {
  if (tickRender) {
    tickRender();
  } else {
    invalidateAnimation();
  }

    if (!nodesDirty && !openDirty) tickRender();
  } else {
    invalidateParticles();
  }
}
```

```typescript
if (!needsLoop) {
```

**Step 2: Modify GraphCanvas.tsx**

2a. Define `handleTickRender` as a stable useCallback (empty deps) BEFORE the `useGraphAnimation` call. It reads everything from refs:
```typescript
const handleTickRender = useCallback(() => {
  const renderer = rendererRef.current;
  if (!renderer) return;
  const s = latestRenderStateRef.current;
  if (!s) return;

  // Build renderNodes imperatively (same logic as renderNodes useMemo)
  const dimmedBySearch = s.searchActive;
  const nodes: NodeRenderModel[] = s.visibleDisplayNodes.map((pos) => {
    const id = pos.node.id;
    const override = animatedPositionsRef.current.get(id);
    const x = override?.x ?? pos.x;
    const y = override?.y ?? pos.y;
    const isOpen = s.openNodeIds.has(id);
    return {
      id,
      node: pos.node,
      x, y,
      width: s.nodeWidth,
      height: s.nodeHeight,
      isCurrent: s.currentNodeId === id,
      isOpen,
      openProgress: s.display.dimClosedNodes
        ? (openProgressRef.current.get(id) ?? (isOpen ? 1 : 0))
        : 1,
      tabCount: s.nodeTabCounts[id] ?? 0,
      ...(s.tabStates[id] !== undefined ? { tabState: s.tabStates[id] } : {}),
      isCollapsed: s.collapsedNodeIds.has(id),
      isSelected: false,
      isPreview: false,
      isSearchMatch: s.searchSet.has(id),
      isSearchFocused: s.focusedSearchId === id,
      isSearchDimmed: dimmedBySearch && !s.searchSet.has(id),
      isHoverFocused: s.hoverNodeId === id,
      display: s.display,
      tagDefs: s.tagDefs,
    };
  });

  // Build connectionPositions imperatively (same logic as connectionPositions useMemo)
  let connPositions = s.positions;
  if (animatedPositionsRef.current.size > 0) {
    const next = new Map();
    s.positions.forEach((pos, id) => {
      const override = animatedPositionsRef.current.get(id);
      if (override) {
        next.set(id, { ...pos, x: override.x, y: override.y });
      } else {
        next.set(id, pos);
      }
    });
    connPositions = next;
  }

  // Build connections (reuse buildConnections)
  const conns = s.effectiveShowConnections
    ? buildConnections(s.root, connPositions, s.pathNodeIds, s.layoutMode, s.hideTreeRoot, s.nodeWidth, s.nodeHeight)
    : [];

  // Handle dragReparentTarget preview connection if active
  // (same logic as connections useMemo — apply drag reparent filter/preview)
  const finalConns = applyDragReparentPreview(conns, connPositions, s);

  renderer.setDynamicState({ nodes, connections: finalConns, showConnections: s.effectiveShowConnections });

  // Build particle render models imperatively
  const particles = particleAnimationsRef.current.map((p) => {
    const progress = Math.min(1, p.age / p.life);
    const eased = easeOutCubic(progress);
    return {
      id: p.id,
      x: lerp(p.startX, p.endX, eased),
      y: lerp(p.startY, p.endY, eased),
      radius: p.radius,
      alpha: Math.max(0, 1 - progress),
    };
  });
  renderer.setParticles(particles);
}, []);
```

NOTE on the drag reparent preview: Extract the drag reparent logic from the existing `connections` useMemo (lines 1209-1268) into a small helper function `applyDragReparentPreview(baseConns, connPositions, state)` that both the useMemo and `handleTickRender` can call. This avoids duplicating the bezier/preview connection logic. Alternatively, since drag-reparent doesn't happen during animation (user is dragging, not animating), the imperative path can skip this and just pass `conns` directly.

SIMPLIFICATION: Drag reparent and animation don't overlap. When dragging, there's no expand/collapse animation running. So `handleTickRender` can skip the dragReparentTarget logic entirely and just use `conns` directly. This is correct because `onTickRender` only fires during animation ticks, and drag reparent is a separate interaction.
