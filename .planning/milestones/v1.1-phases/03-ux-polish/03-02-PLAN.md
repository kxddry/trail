The context menu system has two menu components:
1. `NodeContextMenu` — single node right-click menu

Existing confirmation pattern (NodeContextMenu only):
- Uses `pendingDelete` state: `useState<string | null>(null)` with values 'node', 'children', 'withChildren'

BulkContextMenu destructive actions (NO confirmation currently):
- "Delete nodes" → `rpc.bulkDeleteNodes({ nodeIds })`

Also destructive but lower-risk (no confirmation needed):
- "Close tab" / "Close all tabs" — tabs can be reopened
- "Close selected tabs" — can be reopened

**BulkContextMenu — add confirmation for destructive actions (UX-04):**

Add `pendingDelete` state to BulkContextMenu, mirroring the pattern from NodeContextMenu:
```typescript
const [pendingDelete, setPendingDelete] = useState<string | null>(null);
```

For "Delete nodes recursively" item:
- First click: `setPendingDelete('recursive')` — item text changes to "Confirm delete?"
- Second click (when `pendingDelete === 'recursive'`): execute `rpc.bulkDeleteRecursive` and close

Use the same `.danger.is-confirming` class that NodeContextMenu already uses for the confirmation state.

**NodeContextMenu — verify existing pattern:**

The CONTEXT.md says to use shadcn AlertDialog, but the existing inline confirm pattern is already superior for this use case — it keeps the user in flow without a modal popup.

**ContextMenus.tsx — ARIA roles (UX-06):**

Apply ARIA roles consistently across ALL menu items in both NodeContextMenu and BulkContextMenu:

1. **Every `.graph-context-menu-item` div** that acts as a clickable action must have:
   - `role="menuitem"`
   - `tabIndex={-1}`
   Many items already have these, but several are missing them. Add to ALL actionable items including:
   - Pin/Unpin
   - Collapse/Expand node
   - Copy URL / Copy title
   - Duplicate at...
   - Close tab / Close all tabs
   - Pin selected / Unpin selected
   - Collapse selected / Expand selected
   - Close selected tabs
   - All delete items (both pending and confirming states)

2. **Divider divs** (`.graph-context-menu-divider`): Add `role="separator"`

3. **Header divs** (`.graph-context-menu-header`): Add `role="presentation"` — these are visual labels, not interactive

4. **Submenu container** (`.graph-context-submenu`): Add `role="menu"` to submenu containers (Tags submenu)

5. **Tag items** in submenu: Add `role="menuitemcheckbox"` and `aria-checked={hasTag}` since they toggle tag on/off

6. **Tab items** in the tabs list: Add `role="menuitem"` and `tabIndex={-1}`

7. **Disabled items** (`.is-disabled`): Add `aria-disabled="true"` (already present on some via className, but add the explicit ARIA attribute)

**context-menus.css — keyboard focus styles:**

Add `:focus-visible` styles for keyboard navigation on menu items:

```css
.graph-context-menu-item:focus-visible {
  outline: 2px solid var(--ring, currentColor);
  outline-offset: -2px;
  border-radius: 4px;
  background: var(--glass);
}

.graph-context-tab-item:focus-visible {
  outline: 2px solid var(--ring, currentColor);
  outline-offset: -2px;
}

.graph-context-tab-action:focus-visible {
  outline: 2px solid var(--ring, currentColor);
  outline-offset: 1px;
}
```

Add reduced motion for context menu open animation:
```css
@media (prefers-reduced-motion: reduce) {
  .graph-context-menu {
    animation: none;
  }
  .graph-context-submenu {
    transition: none;
  }
}
```
