**A. Local camera state during pan/zoom (useGraphView.ts)**

Modify `scheduleGraphView` to stop calling `onGraphViewChange(next)` during every RAF frame. Instead:

1. During active gestures, only update `viewRef.current`, call `rendererRef.current?.setView()`, and call `applyGridTransform()` -- do NOT call `onGraphViewChange()`.
2. Add a new `commitViewToStore` helper that calls `onGraphViewChange(viewRef.current)` once.
3. Call `commitViewToStore` only in these scenarios:
   - `handlePointerUp` (pan ends) -- add a new `onGestureEnd` callback returned from the hook
   - Wheel idle -- add a `wheelIdleTimerRef` (150ms setTimeout in `scheduleGraphView`). On each wheel event, clear the previous timer and set a new one. When the timer fires, call `commitViewToStore`.
   - `fitToView` and `centerOnNode` already call `onGraphViewChange` directly -- keep those as-is.
   - `animateViewTo` already calls `onGraphViewChange` per frame -- keep that as-is (view animations are brief and need store sync for other consumers).
4. Return `commitViewToStore` from the hook so GraphCanvas can call it on pointerUp.
5. On unmount, if `pendingViewRef.current` or the viewRef differs from last committed, flush to store.

The key insight: `viewRef.current` is already the source of truth for the renderer and grid. The Zustand store only needs the final resting position for persistence/restoration.

**B. Local hover state with debounce (GraphCanvas.tsx)**

The hover state is already optimized -- `hoverNodeId` does NOT appear in the `renderNodes` useMemo deps (it was removed in Phase 5 of the perf work). The only cost is the Zustand write itself + any subscribers. Optimize:

1. In `handlePointerMove`, instead of calling `onSetHoverNodeId(hitNodeId)` immediately, push hover directly to the renderer via `rendererRef.current?.setHoverNodeId(hitNodeId)` for instant visual feedback.
2. Debounce the `onSetHoverNodeId` Zustand write with an 80ms timeout. Use a `hoverDebounceRef = useRef<number | null>(null)`. On each hover change:
   - Call `rendererRef.current?.setHoverNodeId(hitNodeId)` immediately (visual feedback).
   - Clear previous debounce timer, set new 80ms timer that calls `onSetHoverNodeId(hitNodeId)`.
3. In `onPointerLeave`, clear debounce, call both renderer and store immediately (null hover on leave should be instant for cursor changes).
4. The existing `useEffect([hoverNodeId])` that calls `rendererRef.current?.setHoverNodeId(hoverNodeId)` will still fire when the debounced store write triggers a re-render -- but since the renderer already has the correct state, `setHoverNodeId` will early-return (`if (prev === id) return`). No wasted work.
5. Clean up debounce timer on unmount in the existing cleanup effect.

**C. Gesture-aware quality degradation (GraphArea.tsx + GraphCanvas.tsx)**

1. In GraphCanvas.tsx, add a `gestureActiveRef = useRef(false)` and a state `gestureActive` (boolean, default false). Track gesture activity:
   - Set `gestureActiveRef.current = true` + `setGestureActive(true)` when pan starts (`isPanningRef.current = true`), when wheel fires, or when selection box starts.
   - Add a `gestureIdleTimerRef`. On each gesture event (pointer-move during pan, wheel), reset the timer to 200ms. When the timer fires, set `gestureActiveRef.current = false` + `setGestureActive(false)`.
   - On pointerUp (pan end), start the idle timer (200ms before restoring quality).
2. Expose `gestureActive` as a new callback prop: `onGestureActiveChange?: (active: boolean) => void`. Call it from a useEffect on `gestureActive`.
3. In GraphArea.tsx, add `const [gestureActive, setGestureActive] = useState(false)`. Pass `onGestureActiveChange={setGestureActive}` to GraphCanvas.
