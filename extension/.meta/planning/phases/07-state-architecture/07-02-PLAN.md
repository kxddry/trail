<objective>
Enrich the offscreen layout cache key with collapse state hash and recency ordering signature so that warm opens achieve >90% cache hit rate.

Purpose: Currently the offscreen layout cache is keyed by just `treeId` ("active") and validated only by `layoutMode` match. This means any collapse state change or recency ordering toggle invalidates the cache at consumption time (positions don't match the 80% threshold in `hydrateFromCache`). By including collapse state and recency flag in the cache, the offscreen document can pre-compute the correct layout, and consumers can validate the match before hydrating.

Output: Enriched CachedLayoutResult type, storage key incorporating state signature, offscreen document passing collapse/recency state, consumers validating enriched keys.
</objective>

   ```typescript
   export function computeCollapseSignature(collapsedNodeIds: Iterable<NodeId>): string {
     const ids = [...collapsedNodeIds];
     ids.sort((a, b) => a - b);  // NodeId is number
     return ids.join(',');
   }
   ```
   This produces a deterministic string from any Set/Array of collapsed node IDs. Sorting ensures the same set always produces the same signature regardless of insertion order.

**In cache.ts:**

1. Update `storageKey` to include layout mode and state signature. Change from:
   ```typescript
   function storageKey(treeId: string): string {
     return `${PREFIX}${treeId}`;
   }
   ```
   to:
   ```typescript
   function storageKey(treeId: string, layoutMode?: string, collapseSignature?: string, recencyOrdering?: boolean): string {
     // When reading without knowing exact state, use base key for lookup
     if (layoutMode === undefined) return `${PREFIX}${treeId}`;
     // Enriched key for write: includes state that affects layout positions
     const recency = recencyOrdering ? '1' : '0';
     const collapse = collapseSignature || '_';
     return `${PREFIX}${treeId}:${layoutMode}:${collapse}:${recency}`;
   }
   ```

2. Update `writeLayoutCache` to use the enriched key:
   ```typescript
   export async function writeLayoutCache(result: CachedLayoutResult): Promise<void> {
     const storage = getSessionStorage();
     if (!storage) return;
     const key = storageKey(result.treeId, result.layoutMode, result.collapseSignature, result.recencyOrdering);
     // Also write to base key for backward compat / simple lookups
     await storage.set({
       [key]: result,
       [storageKey(result.treeId)]: result,
     });
   }
   ```
   Writing to both keys ensures: (1) enriched key for exact match lookups, (2) base key (`graph-layout:active`) for consumers that don't know the state yet (spotlight-graph reads before knowing collapse state).

3. Update `readLayoutCache` to accept optional state params for exact match:
   ```typescript
   export async function readLayoutCache(
     treeId: string,
     layoutMode?: string,
     collapseSignature?: string,
     recencyOrdering?: boolean,
   ): Promise<CachedLayoutResult | null> {
     const storage = getSessionStorage();
     if (!storage) return null;
     // Try enriched key first if state params provided
     if (layoutMode !== undefined) {
       const enrichedKey = storageKey(treeId, layoutMode, collapseSignature, recencyOrdering);
       const enrichedData = await storage.get(enrichedKey);
       const enrichedEntry = enrichedData[enrichedKey] as CachedLayoutResult | undefined;
       if (enrichedEntry) return enrichedEntry;
     }
     // Fall back to base key
     const key = storageKey(treeId);
     const data = await storage.get(key);
     const entry = data[key] as CachedLayoutResult | undefined;
     return entry ?? null;
   }
   ```

4. `invalidateLayoutCache` stays the same — it removes the base key. For full cleanup, also remove enriched keys via a prefix scan if needed, but `chrome.storage.session` is cleared on browser restart anyway, so the base key removal is sufficient.
