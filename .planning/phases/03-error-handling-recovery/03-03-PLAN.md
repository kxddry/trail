**Part A: GraphCanvas.tsx — Cache corruption recovery (STAB-04)**

1. Wrap both call sites of `hydrateFromCache` (around lines 513 and 530) in try/catch blocks. On catch:
   - Log: `console.error("[GraphCanvas] Cache hydration failed, clearing corrupt entry:", error)`
   - Import `toast` from `"sonner"` and call: `toast.warning("Layout cache was corrupted and has been reset")`
   - Import `invalidateLayoutCache` from `@shared/graph-layout-cache/cache.js` and call it with the current treeId to surgically remove the broken entry (NOT a full wipe)
   - Set `_prefetchedLayout = null` so subsequent logic falls through to fresh layout computation
   - Continue execution (no throw) — the graph will compute layout from scratch

The pattern at each call site should become:
```typescript
let hydrated: { positions: Map<NodeId, NodePosition>; width: number } | null = null;
if (_prefetchedLayout) {
  try {
    hydrated = hydrateFromCache(_prefetchedLayout, root);
  } catch (cacheError) {
    console.error("[GraphCanvas] Cache hydration failed, clearing corrupt entry:", cacheError);
    toast.warning("Layout cache was corrupted and has been reset");
    void invalidateLayoutCache(treeId);
    _prefetchedLayout = null;
  }
}
```

Ensure `treeId` is accessible at both call sites. Read the surrounding code to determine how treeId is available (likely from the tree prop or from the cached layout result's treeId field: `_prefetchedLayout.treeId`).

**Part B: offscreen-graph-manager.ts — Offscreen fallback toast (STAB-05)**

The offscreen-graph-manager runs in the background service worker. The background cannot directly call `toast()` (sonner only works in UI contexts). Instead, the existing pattern is to send an RPC notification to the UI.

However, looking at the CONTEXT.md decision: "Add toast.warning: 'Using basic layout mode'" — this notification needs to reach the sidepanel UI.

Two approaches:
1. **If the sidepanel UI detects offscreen failure**: The GraphCanvas already falls back to synchronous layout when offscreen doesn't respond. Add the toast there instead.
2. **Direct notification**: Since `ensureOffscreenDocument` runs on service worker startup and the sidepanel may not be open yet, the most practical place is in the GraphCanvas/layout code when it detects offscreen is unavailable and falls back.

**Chosen approach**: Add the toast in the offscreen fallback path within the graph layout code. Search GraphCanvas.tsx or the layout pipeline for where offscreen failure is detected and synchronous layout is used as fallback. Add `toast.warning("Using basic layout mode")` at that fallback point.

If the fallback detection is in `offscreen-graph-manager.ts` itself (background context), instead store a flag and have the UI read it. But first check GraphCanvas.tsx for offscreen fallback detection.

If the offscreen fallback is detected purely in background with no UI signal, then modify `ensureOffscreenDocument` to set a flag (e.g., on a storage key or a global) that the UI can check:

```typescript
// In offscreen-graph-manager.ts:
let offscreenFailed = false;
export function didOffscreenFail(): boolean { return offscreenFailed; }

// In the catch block of ensureOffscreenDocument:
catch (err) {
  offscreenFailed = true;
  console.warn("[offscreen-graph-manager] failed to create offscreen document:", err);
}
```

Then in the graph layout code on the UI side, when it detects offscreen is unavailable and falls back to sync layout, show: `toast.warning("Using basic layout mode")`

**Key per CONTEXT.md**: No retry for offscreen failure — it is typically persistent. Just show the warning once.

**Part B: TreeDropdown.tsx — Stub tree error handling (HYG-06)**

2. In `handleOpen`, update the stub tree error handling. Currently:
```typescript
if (tree.stub) {
  setLoadingTreeId(tree.id);
  await ensureTreeLoaded(tree.id);
}
await openTree(tree.id);
```

Change to:
```typescript
if (tree.stub) {
  setLoadingTreeId(tree.id);
  try {
    await ensureTreeLoaded(tree.id);
  } catch (loadError) {
    showOperationError("Load tree from cloud", loadError);
    setUnavailableTreeIds(prev => new Set(prev).add(tree.id));
    setLoadingTreeId(null);
    return; // Don't try to open — keep dropdown open
  }
}
try {
  await openTree(tree.id);
} catch (openError) {
  showOperationError("Open tree", openError);
}
```
