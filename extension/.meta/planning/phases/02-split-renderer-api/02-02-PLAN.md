Key data flow in GraphCanvas:
- `basePositions` — output of layout algorithm, changes on topology/layout change
- `positions` — basePositions + computeOffsetPositions (drag preview), changes on layout or drag
- `animatedPositionsRef` — animation deltas in a ref, not React state
- `animationVersion` — counter bumped each animation frame to trigger useMemo recompute
- `renderNodes` — useMemo that merges positions + animatedPositionsRef overrides + hover/search/openProgress
- `connectionPositions` — useMemo that merges positions + animatedPositionsRef overrides
- `connections` — useMemo that builds ConnectionSegment[] from connectionPositions + path + drag preview

The challenge: `renderNodes` and `connections` are recomputed on BOTH topology change AND animation tick.
We need to detect WHICH kind of change triggered the useEffect.

Strategy: Use a ref to track whether the most recent change was a topology/layout change or a dynamic-only change. When `basePositions`, `layoutOptions.mode`, `nodeWidth`, `nodeHeight` change, that is static. When only `animationVersion`, `hoverNodeId`, `search`, `openNodeIds` change, that is dynamic.

**Add a version counter ref to discriminate static vs dynamic changes.**

Add these refs near the other refs in the component body (around line 210-220 area):

```typescript
const staticVersionRef = useRef(0);
const prevStaticDepsRef = useRef<{ layoutMode: LayoutMode; nodeWidth: number; nodeHeight: number; basePositions: Map<NodeId, NodePosition> } | null>(null);
```

Then add a useMemo right after the `positions` computation (around line 397, BEFORE the `displayNodes`/`renderNodes` useMemos) to detect static changes and increment the counter:

```typescript
const staticVersion = useMemo(() => {
  const prev = prevStaticDepsRef.current;
  if (prev === null) {
    prevStaticDepsRef.current = { layoutMode: layoutOptions.mode, nodeWidth, nodeHeight, basePositions };
    staticVersionRef.current += 1;
    return staticVersionRef.current;
  }
  const changed =
    prev.layoutMode !== layoutOptions.mode ||
    prev.nodeWidth !== nodeWidth ||
    prev.nodeHeight !== nodeHeight ||
    prev.basePositions !== basePositions;
  prevStaticDepsRef.current = { layoutMode: layoutOptions.mode, nodeWidth, nodeHeight, basePositions };
  if (changed) {
    staticVersionRef.current += 1;
  }
  return staticVersionRef.current;
}, [layoutOptions.mode, nodeWidth, nodeHeight, basePositions]);
```

Now create the three useEffects to replace the old single `setData` useEffect:

**useEffect A — Static graph (fires only on topology/layout changes):**
```typescript
useEffect(() => {
  rendererRef.current?.setStaticGraph({
    nodes: renderNodes,
    connections,
    layoutMode: layoutOptions.mode,
    nodeWidth,
    nodeHeight,
    showConnections: effectiveShowConnections,
  });
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [staticVersion]);
```

This fires ONLY when `staticVersion` changes (layout mode, node dimensions, or base positions changed). The eslint-disable is necessary because `renderNodes`, `connections`, etc. are consumed but not listed as deps — they are always fresh at call time since `staticVersion` only changes in the same render cycle as the static deps.

**useEffect B — Dynamic state (fires on animation, hover, search, openProgress changes):**
```typescript
useEffect(() => {
  rendererRef.current?.setDynamicState({
    nodes: renderNodes,
    connections,
    showConnections: effectiveShowConnections,
  });
}, [renderNodes, connections, effectiveShowConnections]);
```

This fires on ANY change to renderNodes (animation ticks, hover, search, openProgress) or connections. It also fires when static changes happen — that is harmless because `setStaticGraph` runs first and `setDynamicState` is cheap (no SpatialIndex rebuild).

**useEffect C — Particles:**
```typescript
useEffect(() => {
  rendererRef.current?.setParticles(particleRenderModels);
}, [particleRenderModels, particleVersion]);
```
