<task type="auto">
  <name>Task 2: Create extension release workflow (CICD-07)</name>
  <files>.github/workflows/release-extension.yml</files>
  <action>
Create `.github/workflows/release-extension.yml` with the following specification:

**Triggers:**
- `push.tags`: pattern `chrome-v*` (e.g., `chrome-v0.9.2`)
- `workflow_dispatch`: for manual re-runs

**Concurrency:**
- Group: `release-extension` (no ref — only one release at a time)
- `cancel-in-progress: false` (do NOT cancel in-progress releases)

**Permissions:**
- `contents: write` (needed for GitHub Release creation)

**Job: `release`** (runs-on: `ubuntu-latest`)

Default working directory: `extension`

**Steps:**

1. **Checkout** — `actions/checkout@v6`

2. **Setup pnpm** — `pnpm/action-setup@v4` with version `10.29.3`

3. **Setup Node** — `actions/setup-node@v6` with node-version `20`, cache `pnpm`, cache-dependency-path `extension/pnpm-lock.yaml`

4. **Install** — `pnpm install --frozen-lockfile`

5. **Typecheck** — `pnpm typecheck`

6. **Test** — `pnpm test`

7. **Build** — `pnpm build`

8. **Package** — `pnpm zip`
   The zip output path will be `extension/.output/` and the file is named like `trail-{version}-chrome.zip`.

9. **Extract version from tag** — Use shell to strip `chrome-v` prefix from `${{ github.ref_name }}`:
   ```
   echo "VERSION=${GITHUB_REF_NAME#chrome-v}" >> $GITHUB_ENV
   ```
   This is the simplest version strategy per user's discretion allowance — the tag IS the version source of truth.

10. **Find zip file** — Locate the built zip in `.output/`:
    ```
    ZIP_PATH=$(ls .output/*-chrome.zip | head -1)
    echo "ZIP_PATH=$ZIP_PATH" >> $GITHUB_ENV
    echo "ZIP_NAME=$(basename $ZIP_PATH)" >> $GITHUB_ENV
    ```
    Note: this step's working directory is `extension`, so the path is relative.

11. **Upload to Chrome Web Store (draft)** — Use the `nicolo-ribaudo/chrom-webstore-upload` action (widely adopted, simple). Configure with:
    - `extension-id: ${{ secrets.CWS_EXTENSION_ID }}`
    - `client-id: ${{ secrets.CWS_CLIENT_ID }}`
    - `client-secret: ${{ secrets.CWS_CLIENT_SECRET }}`
    - `refresh-token: ${{ secrets.CWS_REFRESH_TOKEN }}`
    - `file-name: ${{ env.ZIP_PATH }}`
    - `publish: false` (upload as draft — user manually publishes from Chrome Developer Dashboard)

    If this action is unavailable or problematic, fall back to `AButler/upload-release-assets` pattern or direct curl to the Chrome Web Store API. The key requirement is: upload the zip as a draft, do not auto-publish.

    **Important:** This step should use `working-directory: extension` (set via job defaults) so the relative path works. If the action needs an absolute path, prefix with `extension/`.

12. **Create GitHub Release** — Use `softprops/action-gh-release@v2`:
    - `tag_name: ${{ github.ref_name }}`
    - `name: Extension v${{ env.VERSION }}`
    - `draft: false`
    - `prerelease: false`
    - `generate_release_notes: true` (GitHub auto-generates from commits — simple, no custom format needed)
    - `files: ${{ env.ZIP_PATH }}`

**Environment variable summary:**
- `CWS_EXTENSION_ID` — GitHub secret
- `CWS_CLIENT_ID` — GitHub secret
- `CWS_CLIENT_SECRET` — GitHub secret
- `CWS_REFRESH_TOKEN` — GitHub secret

**Pattern alignment:**
- Mirror the setup steps from `ci-extension.yml` exactly (checkout, pnpm, node, install)
- Add typecheck/test/build before packaging (belt-and-suspenders per user decision)
- No concurrency `cancel-in-progress` on releases (unlike CI which cancels)
