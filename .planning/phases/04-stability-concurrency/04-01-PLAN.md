**useBootstrap.ts — STAB-02 re-entry guard (per user decision):**
Add a `bootstrapInFlight` ref (`useRef(false)`) to useBootstrap. At the top of the useEffect async IIFE, check `if (bootstrapInFlight.current) return;` and set it to `true`. In the cleanup function AND at the end of the async IIFE (both success and failure paths), set `bootstrapInFlight.current = false`. The existing `mounted` ref is still needed for component unmount — `bootstrapInFlight` prevents overlapping Promise.all calls when the effect re-fires due to rapid open/close. Do NOT remove the existing `mounted` check.

**TreeDropdown.tsx — STAB-03 double-submit on rename + deleteArchived (per user decision):**
1. Add `const [renamePending, setRenamePending] = useState(false);` near existing state declarations.
2. In `commitEdit`: add early return `if (renamePending) return;` at top. Wrap the try/catch body: `setRenamePending(true)` before `await renameTree(...)`, `setRenamePending(false)` in finally block.
3. Add `const [deletePending, setDeletePending] = useState<string | null>(null);` to track which archived tree is being deleted.
4. In `handleDeleteArchived`: add early return `if (deletePending === treeId) return;`. Set `setDeletePending(treeId)` before await, `setDeletePending(null)` in finally.
5. On the delete button in the archived tree row, add `disabled={deletePending === tree.id}`. On the input blur/keydown for rename, the existing `commitEdit` will now be guarded.

**ContextMenus.tsx — STAB-03 double-submit on node-delete, bulk-delete, bulk-delete-recursive (per user decision):**
1. In `NodeContextMenu` component: add `const [deletingNode, setDeletingNode] = useState(false);` state.
2. In the "Confirm delete?" onClick handler for single node delete (line ~722), wrap: `if (deletingNode) return; setDeletingNode(true);` before `fireAndForget(rpc.deleteNode(...))`. The `closeContextMenu()` call immediately after means the component unmounts, so no finally needed — but add it for safety: call `fireAndForget` then `closeContextMenu()`.
3. In `BulkContextMenu` component: add `const [deletingBulk, setDeletingBulk] = useState(false);` state.
4. In the "Confirm delete?" onClick for bulk-delete (line ~1000) and bulk-delete-recursive (line ~1023), add `if (deletingBulk) return; setDeletingBulk(true);` before the `fireAndForget` call.
5. Keep the `pendingDelete` two-step confirmation pattern intact — isPending guards only prevent the SECOND click on the already-confirmed "Confirm delete?" item.
