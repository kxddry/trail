    **Part B: Partial offset computation during drag (INTR-02)**

    In graph-layout-compute.ts, add a new function `computeDragOffsetPositions` that takes the previous positions map and only recomputes positions for nodes whose offsets changed (the dragged subtree IDs + their ancestors up to root):

    ```typescript
    export function computeDragOffsetPositions(
      basePositions: Map<NodeId, NodePosition>,
      prevPositions: Map<NodeId, NodePosition>,
      mode: LayoutMode,
      nodeWidth: number,
      nodeHeight: number,
      root: NavigationNode | null,
      dragPreview: LayoutUpdateMap,
      affectedIds: Set<NodeId>,
    ): Map<NodeId, NodePosition>
    ```

    Implementation for tree/mindmap mode:
    - Start with a shallow copy of prevPositions (Map constructor)
    - Only run computeOffset for nodes in affectedIds
    - For each affected node, recompute offset and update the position in the new map
    - Non-affected nodes keep their previous positions (already in the map)

    For radial mode: same approach but using computeRadialOffset on affectedIds only.

    In GraphCanvas.tsx, modify the `positions` useMemo (around line 503):

    - When `dragPreview` is null (not dragging), call the existing `computeOffsetPositions` as before
    - Store the previous positions in a ref (`prevDragPositionsRef`) to enable incremental updates
    - Compute affectedIds: collect the dragged subtree IDs from dragStateRef, plus walk ancestors from each dragged node to root

    The affectedIds set should be computed once at drag start and stored in dragStateRef, not recomputed per frame.
