    **Step 3 — Reset dismiss on meaningful state change:**

    The banner should reappear when a new auth event occurs. In `App.tsx`, the `showSessionBanner` condition already depends on `account.sessionExpired` — when the user authenticates and session is restored, `sessionExpired` becomes false, and the banner hides naturally.

    When session expires AGAIN (new session expiry), the banner needs to show even if previously dismissed. Handle this by clearing the dismissed flag when `account.sessionExpired` transitions to `true`:

    In `SessionExpiredBanner.tsx`, the component only renders when `showSessionBanner` is true (controlled by App.tsx). It won't render when session is valid. When session expires again, App.tsx will render it again, and we need the dismissed flag to be false.

    Add a reset mechanism: In the parent (`App.tsx`), when `showSessionBanner` transitions from false to true, clear the storage flag. OR, simpler: In `SessionExpiredBanner.tsx`, add a mount-time effect that clears the flag since the component only mounts when the session is expired. This ensures each new session expiry starts fresh:

    Actually, the simplest correct approach: The component is conditionally rendered by App.tsx only when session is expired. Each time it mounts (new session expiry), reset the dismissed flag:

    ```typescript
    // On mount = new session expiry event, reset dismiss
    useEffect(() => {
      sessionBannerDismissedItem.setValue(false).catch(() => {});
    }, []); // Runs once on mount
    ```

    Wait — this conflicts with the persistence goal. The scenario is:
    1. Session expires -> banner shows
    2. User dismisses -> persisted to session storage
    3. User closes and reopens panel -> banner should NOT show (within same browser session)
    4. Session expires AGAIN (different event) -> banner SHOULD show

    The problem is distinguishing "reopen after dismiss" from "new expiry". Solution: Store a timestamp instead of boolean. When dismissing, store `Date.now()`. On mount, check if the stored timestamp is recent (e.g., within the current session). But session storage already clears on browser restart.

    Simplest correct approach: Don't reset on mount. The storage is session-scoped so it auto-clears on browser restart. For "new auth event" reappearance: when auth succeeds (session becomes valid), clear the dismiss flag. Do this in the `watch` pattern:

    In `SessionExpiredBanner.tsx`, the component unmounts when session becomes valid (App.tsx stops rendering it). Then when session expires again, it remounts. On mount, load the flag. If user signed in and out, the flag is still `true` from the previous dismiss.

    Better: Clear the flag when auth state changes to non-expired. Since the component is unmounted at that point, do it in `App.tsx` or via a storage watcher.

    Cleanest approach: In `App.tsx`, add a one-line effect:
    ```typescript
    // Clear session banner dismiss when auth is restored
    useEffect(() => {
      if (!account.sessionExpired) {
        sessionBannerDismissedItem.setValue(false).catch(() => {});
      }
    }, [account.sessionExpired]);
    ```

    This means: when the user authenticates (sessionExpired becomes false), clear the dismiss flag. Next time session expires, banner shows again.
