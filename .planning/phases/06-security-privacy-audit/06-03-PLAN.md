    Per SEC-08: Add Zod validation at background ingress in site-message-handlers.ts.

    The current flow: content script validates envelope (origin, nonce, TTL) then forwards
    a SITE_MESSAGE_FORWARD with { siteMessageType, payload, requestId }. The payload arrives
    as Record<string, unknown> and inner handlers use manual typeof guards.

    Replace with Zod validation:

    1. Import the per-type schemas from site-messages.ts:
    ```typescript
    import {
      PingMessage as PingSchema,
      AuthRevokedMessage as AuthRevokedSchema,
      EnterEditorModeMessage as EnterEditorSchema,
      ExitEditorModeMessage as ExitEditorSchema,
      SaveEditorModeMessage as SaveEditorSchema,
      CancelEditorModeMessage as CancelEditorSchema,
      AuthCodeRelayMessage as AuthCodeRelaySchema,
      type SiteMessageTypeName,
    } from "../../../shared/schemas/site-messages.js";
    ```

    2. Create a schema lookup map (only for types that have payload fields that need validation):
    ```typescript
    import type { z } from "zod";

    const payloadSchemas: Partial<Record<string, z.ZodType>> = {
      ENTER_EDITOR_MODE: EnterEditorSchema,
      AUTH_CODE_RELAY: AuthCodeRelaySchema,
    };
    ```

    3. In the SITE_MESSAGE_FORWARD handler, BEFORE dispatching to innerHandlers, validate
    the payload for message types that have schemas with fields beyond the base:
    ```typescript
    // Validate payload for types with typed fields
    const schema = payloadSchemas[siteMessageType];
    if (schema) {
      // Reconstruct a full message shape for Zod (it expects source, type, requestId, timestamp)
      const fullMessage = {
        source: "trail-site" as const,
        type: siteMessageType,
        requestId,
        timestamp: Date.now(),
        ...payload,
      };
      const parsed = schema.safeParse(fullMessage);
      if (!parsed.success) {
        console.warn("[site-msg] Payload validation failed:", siteMessageType, parsed.error.issues);
        return err(`Invalid payload for ${siteMessageType}: ${parsed.error.issues[0]?.message ?? "unknown"}`);
      }
    }
    ```

    4. Now update the inner handlers to use validated data. For ENTER_EDITOR_MODE:
    - Remove the manual typeof guard: `const treeId = typeof payload.treeId === "string" ? payload.treeId : "";`
    - Replace with: `const treeId = payload.treeId as string;` (Zod already validated it)
    - Keep the `if (!treeId)` check as a defense-in-depth empty string guard

    5. For AUTH_CODE_RELAY:
    - Remove manual typeof guards for code, codeVerifier, redirectUri
    - Replace with direct access: `const { code, codeVerifier, redirectUri } = payload as { code: string; codeVerifier: string; redirectUri: string };`
    - Keep the `if (!code || !codeVerifier || !redirectUri)` check as defense-in-depth

    6. For types without payload fields (PING, AUTH_REVOKED, EXIT_EDITOR_MODE, SAVE_EDITOR_MODE, CANCEL_EDITOR_MODE): no change needed -- the base envelope validation in the content script is sufficient for parameterless messages.

    Note: Use console.warn for the validation failure log line (this file will be migrated to createLogger by plan 02, but the plans run in parallel so use raw console here -- plan 02 will catch it in migration).
