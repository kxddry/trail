**Types:**
```typescript
export type RestoreEntry = {
  nodeId: NodeId;
  priority: number; // lower = higher priority (0 = current, 1 = hover, etc.)
};
```

**Priority scoring function** `computeRestorePriority(nodeId, model, viewportCenter, selectedIds, searchFocusedId, pathNodeIds)`:
- Priority 0: `model.isCurrent` (current node)
- Priority 1: `model.isHoverFocused` (hovered node)
- Priority 2: `selectedIds.has(nodeId)` (selected nodes)
- Priority 3: `model.isSearchFocused` (search-focused node)
- Priority 4: `pathNodeIds?.has(nodeId)` (path nodes — pass null if not applicable)
- Priority 5: distance-based from viewport center — nodes closer to `viewportCenter: {x, y}` get priority 5, farther nodes get priority 6
  - Distance threshold: use median of all candidate distances as the split point (viewport-center-half vs rest)
  - For the distance sub-sort within same priority tier, sort ascending by euclidean distance to viewportCenter
- Priority 6: everything else (far from viewport center)

**Sort function** `sortRestoreQueue(entries: RestoreEntry[]): RestoreEntry[]`:
- Returns a NEW sorted array (immutable — do not mutate input)
- Sort by `priority` ascending, then by secondary distance key if same priority

**Batch budget calculator** `computeBatchBudget(totalNodeCount: number): { batchSize: number; deadlineMs: number }`:
- Small tree (<500 nodes): `batchSize = 60`, `deadlineMs = 8`
- Medium tree (500-1500 nodes): `batchSize = 30`, `deadlineMs = 6`
- Large tree (>=1500 nodes): `batchSize = 15`, `deadlineMs = 4`
- These are initial values; the key contract is that ALL sizes use the budgeted path

Export all three: `computeRestorePriority`, `sortRestoreQueue`, `computeBatchBudget`.

Import `NodeId` from `@shared/types/ids.js`. Import `NodeRenderModel` from `./types.js` if needed for the model parameter type, or accept a minimal interface `{ isCurrent: boolean; isHoverFocused: boolean; isSearchFocused: boolean; x: number; y: number }` to keep the module lightweight.
